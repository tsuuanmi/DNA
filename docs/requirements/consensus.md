# Sample consensus requirements

**Requirement namespace:** `SRS-CONS-*`

Design: [[design/consensus|consensus method]]. Contract:
[[reference/consensus|consensus result]]. Decision:
[[ADR-0073]], [[ADR-0074]].

- **SRS-CONS-001:** `dna consensus <sample-id> <trace>... --reference <fasta>` MUST process the traces as `dna sample` does, with rejected reads (SRS-SAMPLE-027, SRS-SAMPLE-029, SRS-SAMPLE-030). It MUST write `results/<sample-id>.consensus.json` (`dna.consensus/v1`) and `results/<sample-id>.consensus.fasta`. It MUST fail without output when every read is rejected or when either target exists.
- **SRS-CONS-002:** The consensus MUST be modality-neutral. It MUST read admitted reads only as `CalledRead` records (`ReadEvidence`, alignment) and MUST NOT use filenames, primer labels, or profile windows.
- **SRS-CONS-003:** Only clean observations MUST decide. A clean observation's calls are unmasked, trusted under `variant_calling.read_end_margin` or exempt from it as the matching or inserted calls, or the reference-matching bounds, of a bounded run before a post-repeat phase loss (ADR-0076, SRS-VAR-013), and carry no modality reason against that use, read by scope as variant calling reads it: an observed base against its base, an inserted base against an indel, and a call beside an insertion or deletion against neither (the inserted calls of an insertion into a repeat the read bounds are judged on the repeat's placements, SRS-VAR-020); a substituted call, or a bound that reads another base, is never exempt. Indels longer than `variant_calling.max_indel_length` are never clean, and neither is a deletion whose neighbouring calls are not trusted. An insertion or deletion that changes the length of a run whose ends the read does not resolve (ADR-0071) MUST NOT be clean. A call its modality vouches for by its base only (scored, its bound withheld) MUST show only its base: it MUST NOT count towards a run's length, show a run's end, make an insertion clean, or bound a clean deletion, and its base MUST NOT be clean where SRS-VAR-018 finds that it may sit one position off, or where it lies on a reference homopolymer of at least four bases whose two bounds the read does not show with calls trusted for more than their base: such a position would carry a run length no read shows.
- **SRS-CONS-004:** Every place where a read cleanly differs from the reference MUST be grown to whole reference runs, together with each neighbouring reference run that a clean substituted base or a clean deletion joins. A reference homopolymer of at least four bases MUST also be a stretch when no read shows it cleanly together with both neighbouring positions while some read differs from the reference on it or its neighbours, cleanly or not; a shorter run MUST NOT, since its disputes are mostly mixed signal. The length is `consensus.seeded_run` (4); it matches the conformance minimum run length of the human-mtDNA profile, which the consensus does not read. Overlapping or touching places MUST merge into one stretch, and a stretch MUST NOT cross the reference origin. A stretch MUST be decided by its run structure (ADR-0074):
  - its composition (the ordered run bases) from reads that read every run cleanly and lose phase at neither edge, where any other read that reads an edge of the stretch cleanly, covering the whole stretch or not, MUST oppose a composition whose first or last runs its clean bases there contradict (a dephased read can swallow a run's exit that an in-phase read of only that end shows); otherwise from the single composition joining one read's clean start to another read's clean end where both reach a common reference position; otherwise the reference's, when a read shows its run structure; otherwise position by position;
  - its run lengths first as whole sequences, from reads that show every run's length, a tie leaving the stretch to the position-by-position decision; otherwise run by run, from reads that show both ends of a run with unmasked run calls;
  - position by position from reads without a clean indel inside it.

  A run end is shown only by a call beyond the run that reads another base: unmasked (`in_phase`), or masked but anchoring, possibly beyond one unresolved call (`anchored_end`). An anchored end placed elsewhere than where reads show that end in phase MUST NOT count. A partly clean run at the inner edge of a read's clean start or end MUST contribute only its base, and a clean start or end that holds every run of the composition while the read reads further runs over the stretch MUST contribute nothing, since it places a run end of the composition inside the stretch.
- **SRS-CONS-005:** Every decision MUST follow rule version 1:
  - all clean observations agree: that sequence;
  - a strict majority wins;
  - one read against one read: the reference sequence, `contested`;
  - any other tie: no sequence, `contested`;
  - no clean observation: `unresolved`.

  A change to the rule MUST raise the `consensus` plugin's method version.
- **SRS-CONS-006:** Segments MUST be maximal runs of decided positions. Undecided positions MUST be written as `N`. A gap of more than `consensus.maximum_undecided_gap` undecided positions MUST split a segment, and a segment with fewer than `consensus.minimum_resolved_bases` resolved bases MUST be dropped.
- **SRS-CONS-007:** The document MUST list:
  - the admitted and rejected reads;
  - every segment, with its reference interval and FASTA record name;
  - every site whose call differs from the reference, that was not called outright, that had disagreeing clean observations, or that holds a run of length evidence `phase_loss` or `reference_frame`, with its supporting, opposing, and uninformative reads and, for a stretch decided by its run structure, each run's length and length evidence (SRS-CONS-008);
  - decision counts, including the runs whose length is `phase_loss` or `reference_frame`.

  It MUST NOT carry a genotype, heteroplasmy fraction, or sample verdict beyond the consensus sequence (SRS-VAR-009).
- **SRS-CONS-008:** A run whose length no read shows MUST take, in order:
  - `confirmed_end`: the count of two reads that agree on it, each entering the run in phase from an opposite end, reading every call of the run unmasked, and losing phase at the other end on a call that does not read the run's base; every such read MUST agree;
  - `reference_frame`: the reference positions between its ends, when every read that shows an end places it alike and every position between is read cleanly by some read;
  - `phase_loss`: otherwise, the longest run read in phase by a read that shows one end and loses phase at the other (its next call masked, unresolved, or unclean and not reading another base);
  - otherwise it stays undecided.

  Each run's length evidence (`in_phase`, `anchored_end`, `confirmed_end`, `phase_loss`, `reference_frame`) MUST be published. The rule MUST NOT use target positions, regions, or conventions.
- **SRS-CONS-009:** A decided site that changes the reference length MUST stay undecided while a position beside it is undecided or uncovered, unless it was decided by its run structure with every run's length shown by a read (`in_phase` or `anchored_end`), since those reads show the run's bounds: otherwise the bases beside an insertion or deletion place it, and inside a repeat they decide which unit changes. Undoing one site can leave another one's neighbour undecided, so the rule MUST apply until nothing changes.
- **SRS-CONS-010:** A reference-only call (ADR-0080) whose base is the reference's at its position, scored and lying beyond `variant_calling.read_end_margin` of every unvouched read end (its modality's own edge verdict does not stand against it), MUST make that position's base observation clean as a confirmation of the reference, and nothing else; so MUST a call within `variant_calling.read_end_margin` of an unvouched read end whose base is the reference's, that its modality vouches for its base (scored, not at an edge, withheld for nothing), with no second base standing out (`SecondBase.stands_out`) and no second peak its modality leaves unexplained, and whose alignment column is not shifted (ADR-0080). A confirmation's run role MUST stay its call's, and no stretch, by its run structure or position by position, MUST count it. A confirmation MUST be withdrawn where a read's call at the position shows a second peak its modality does not explain, unless that read is of the other strand than the confirming read, its second base stands out there, and no read of the confirming strand shows that second base standing out there, at or beside a position where any read observes something other than the reference, cleanly or not (another base, a deletion, or an insertion at a junction beside it), where the position forms a reference run of at least `consensus.seeded_run` bases with a neighbour across a junction no read observes cleanly and no read observes the position cleanly otherwise, where a read of the other strand shows the confirming call's own second base standing out there, and within or beside a decided site that differs from the reference (a site written partly as `N` included), after which the positions MUST be decided again until no confirmation is withdrawn. The positions that only confirmations observe cleanly MUST be published as `reference_only`, and calling the decisions (SRS-VAR-021) MUST treat the call at such a position as showing its base only, so that it bounds no neighbouring run.
- **SRS-CONS-011:** At a site or stretch decided as the reference with reads opposing it (ADR-0083), the opposing reads MUST be set aside when every one of them is on a strand other than that of a supporting read that observes every position of the site cleanly (not as a confirmation), shows no second base standing out there (`SecondBase.stands_out`), and lies at least the needed number of calls from both ends of its informative interval, and either every opposing read shows a second base standing out at some position of the site and no second peak its modality leaves unexplained (`second_unexplained`) there, with the supporting read at least `variant_calling.read_end_margin` calls from its ends; or every opposing read differs there only by insertions or deletions, each within `consensus.dissent_edge` calls of an end of its own informative interval, with the supporting read at least `consensus.dissent_edge` calls from its ends. A set-aside read MUST show nothing at the site, neither a base nor, inside a stretch, a run's length or end, and the site MUST then be decided again, until no read is set aside; the decided value MUST NOT change. At a site or stretch called by a strict majority as a value other than the reference, the first condition MUST apply in the same way to opposing reads that show every call resolved and the decided runs in the same order, differing only in a run's length; any other dissent from such a decision MUST NOT be set aside. A substitution MUST NOT be set aside for its distance from a read end.
- **SRS-CONS-012:** The consensus MUST publish as `unreliable_only` the positions that reads observe only inside their unreliable spans (`ReadEvidence::unreliable`, SRS-CALL-024): a read's call there lies in such a span (a deleted position when the calls on both sides do), and no read shows the position soundly outside its own spans, by a call aligned there that is scored, trusted, and withheld for nothing on its base; each with the reason of the first such span. Calling the decisions (SRS-VAR-021) MUST leave out, from each end of every reportable region inwards, the contiguous `unreliable_only` positions up to the last one the consensus does not settle as the reference (a position in a site that differs from the reference, is undecided, or is contested, or one no segment holds): those positions are not analysed, are not callable, and a change at them is excluded with the span's reason. The `unreliable_only` positions after that last one stay analysed, and so does every position not at a region's own end: a stretch MUST start at the region's first or last position. The review MUST list the stretches not analysed with their reason and MUST hold no item or zone over them, and MUST make a check (`beside_not_analysed`) of every difference DNA calls within `review.edge_zone` positions of a region end it leaves out, since the reads there sit right after their poor start; the EMPOP query MUST list the positions as cut for `not_analysed` (user decision 2026-10-20, [[ADR-0085]]: the poor HVS-II read start is reported as poor data, not analysed).
- **SRS-CONS-013:** Where a stretch decided by its run structure has a call with the reference's run composition over it, and that composition splits two runs of one base by a single-base anchor (on rCRS, HVS-II `303-315`), a run of the two whose length evidence is `anchored_end`, `phase_loss`, or `reference_frame` MUST take the length the two-strand rule decides, with length evidence `two_strand`; a run of evidence `in_phase` or `confirmed_end` MUST keep its length ([[ADR-0074]], [[PROP-0012]] increment 4). No position, target, or profile MUST enter the rule. Each read's tract decode (SRS-CALL-025) MUST be credited to the run its first call's reference position falls in, and gives a strand a view of a run, a top length, the next one, the top's share `p` of the two, and its standard error `SE`: the first-run marginal for that run (`direct`); for the other run, when the decode's mark is the anchor, its total marginal deconvolved by non-negative least squares with the direct run (`derived`); and, only where the strand has no other view of the run, a read the consensus reads in phase through it (`p` = 1, `SE` = 0). The rule MUST decide length `n` only when both strands view the run, every view's top is `n`, and every view satisfies `(p − ½) − max(d, τ) ≥ k · SE`, with `d` the largest `|p_F − p_R|` between a forward and a reverse view, `τ` the view's strand and run noise (`consensus.length_noise_forward`, `consensus.length_noise_reverse`, the run before the anchor first), and `k` `consensus.length_confidence`; otherwise the run MUST keep its length and evidence. A `two_strand` length is observed on both strands, so the run's 3' end stays callable (SRS-VAR-021). The review MUST count a run of evidence `two_strand` as confirmed unless a read's run structure differs from DNA's (SRS-API-020).
- **SRS-CONS-014:** Given the run context of the sample's batch (`dna.run_context/v1`, [[PROP-0014]]), the two-strand rule (SRS-CONS-013) MUST take each run's noise τ as `τ · max(m, √(φ̃ / φ_ref))`, at most ½, with `φ̃ = (n0 · φ_ref + Σz²) / (n0 + n)` over the batch's cross-strand pairs of that run without the sample's own, `n0`, `φ_ref`, and `m` the run's `consensus.length_context_prior_pairs`, `consensus.length_context_reference`, and `consensus.length_context_minimum_scale`; a run with fewer than `consensus.length_context_minimum_pairs` such pairs MUST keep the configured τ. A sample gives a run a cross-strand pair, over each of the profile's recorded anchored windows, when each strand has exactly one view of the run that is not in phase, both with the same top length, at least one with a next length, and both with an `SE`: `d = p_F − p_R` and `z² = d² / (SE_F² + SE_R² + τ_F² + τ_R²)` under the configured τ. The sample's own pairs MUST be taken out when all its reads are among the context's reads and kept when none is; a context that holds only some of them, that was made against another reference, over other windows, or with another τ or other histogram edges (`consensus.length_context_edges`) MUST fail the analysis. Without a context the consensus MUST be the one SRS-CONS-013 decides.
