# Variant Nomenclature Requirements

**Requirement namespace:** `SRS-NOM-*`

These requirements are part of the canonical [DNA SRS](SRS.md).

- **SRS-NOM-001:** Target-specific variant nomenclature MUST be an optional post-calling representation capability. It MUST NOT reinterpret sequencing signal, change caller eligibility, manufacture phase, or change the represented biological haplotype.
- **SRS-NOM-002:** A nomenclature operation consuming a normalization result MUST verify that the supplied reference name and sequence identity match the reference identity carried by that result.
- **SRS-NOM-003:** The represented variant set MUST reconstruct exactly the same complete alternate sequence as the normalized variant set. Source variants, normalized variants, reference identity, and the reconstructed alternate sequence MUST remain available in the result.
- **SRS-NOM-004:** Nomenclature windows, their reference sequences, structures, and ordered rules MUST come from the target profile (SRS-PRF-006). Rule preconditions: `anchored_run_lengths` needs a window of repeat bases around exactly one anchor; `anchor_duplication` and `anchor_deletion` need a repeat base after the anchor; the anchor rules and `terminal_repeat_insertion` need an `anchored_homopolymer` structure; `motif_shift` needs a `tandem_repeat` window ending with its motif. A reference that does not carry every profile window sequence at its position MUST fail explicitly (SRS-PRF-005). SRS-NOM-005, -006, and -013 to -015 specify the shipped human-mtDNA profile (`config/profiles/human-mtdna-rcrs.toml`): HVS-II 303-315 `CCCCCCCTCCCCC` (`T` anchor at 310), HVS-III 513-524 `GCACACACACAC`, and HVS-I 16181-16193 `AAACCCCCTCCCC` (`T` anchor at 16189).
- **SRS-NOM-005:** When the HVS-II alternate window contains only `C` bases around exactly one `T` anchor, sequence-equivalent movement of that anchor MUST be represented as C-run length change at the 309 and 315 boundaries rather than as movement of the anchor base itself.
- **SRS-NOM-006:** Multiple inserted C bases at the left HVS-II run MUST remain anchored after position 309 and multiple inserted C bases at the right run MUST remain anchored after position 315 so an outer notation layer can render ordered forms such as `309.1C`, `309.2C`, and `315.1C`.
- **SRS-NOM-007:** Variants outside every nomenclature window MUST be preserved unchanged. An edit crossing a validated window boundary MUST fail explicitly rather than be partially rewritten.
- **SRS-NOM-008:** Within a window, the first rule whose candidate reconstructs exactly the same window haplotype MUST be used; when no rule applies, the normalized representation MUST be preserved rather than another decomposition invented.
- **SRS-NOM-009:** Nomenclature MUST NOT implement Sanger repeat-artifact interpretation, primer callable ranges, decimal notation rendering, sample reconciliation, or NGS-specific behavior.
- **SRS-NOM-010:** When the target profile declares `notation`, the `sample`, `call`, and `notation` workflows MUST represent each read's eligible variants independently: the profile normalization followed by the profile nomenclature windows. A read with an edit crossing a window MUST keep its normalized representation. When the profile declares no notation the workflow MUST NOT produce notation.
- **SRS-NOM-011:** The `per_base_decimal` notation style MUST render represented variants one call per changed base: a substitution as `<position><base>`, each deleted base as `<position>DEL`, and each inserted base as `<anchor>.<ordinal><base>` after the preceding reference base (anchor `0` before position 1), ordered by position and then ordinal.
- **SRS-NOM-012:** Sample notation MUST list each distinct rendered call with every read whose represented variants contain it, in read-registry order. It MUST NOT include ineligible observations, infer reference support from a read's silence, or adjudicate disagreement between reads.
- **SRS-NOM-013:** After the run-length rule (SRS-NOM-005), HVS-II MUST represent a duplicated anchor as `311T 315.1C`, an anchor deletion as `310C 315DEL`, and a one-base gain ending in `C` as position-wise substitutions plus `315.1C` (EMPOP terminal insertion), the last only when that needs no more edits than the normalized form. A substitution without length gain MUST NOT gain `315.1C`.
- **SRS-NOM-014:** HVS-III MUST represent the loss of exactly one `AC` motif copy as position-wise substitutions against the remaining reference plus deletion of the terminal copy (`523DEL 524DEL`), for example `513A 523DEL 524DEL`.
- **SRS-NOM-015:** HVS-I MUST represent the haplotype of `16183C 16184A 16189C` in that phylogenetic form whatever its source decomposition, and an anchor deletion as `16189C 16193DEL`.
- **SRS-NOM-016:** When the profile declares conformance, `notation` MUST check each read's represented variants against the declared rules (`insertion_at_run_end`, `insertion_matches_run`) over reference homopolymers of at least `minimum_run_length` bases and MUST report every finding without changing any represented call or the reconstructed haplotype.
