# Primary-sequence Difference Requirements

**Requirement namespace:** `SRS-VAR-*`

These requirements are part of the canonical [DNA SRS](SRS.md).

- **SRS-VAR-001:** Variants MUST derive only from the selected primary-sequence alignment.
- **SRS-VAR-002:** Canonical primary A/C/G/T mismatches MAY produce normalized SNV observations; unresolved primary N differences MUST be excluded and counted. A mixed call may still produce a primary-sequence difference from its strongest channel, but mixed supporting signal MUST remain explicit and MUST NOT be presented as an ordinary clean SNV.
- **SRS-VAR-003:** Contiguous gaps MAY produce insertions/deletions no longer than configured changed length, excluding the anchor.
- **SRS-VAR-004:** Indel representation MUST preserve the canonical gap placement selected by alignment under `SRS-ALN-012` in the [alignment requirements](alignment.md); variant construction MUST NOT independently left-shift, rotate, or otherwise move a repeat-equivalent indel. When no aligned left flank exists, the actual reference predecessor MUST be derived when possible; a true leading linear insertion/deletion MUST use a real right-anchor representation. Circular origin-spanning representation MUST preserve the alignment-selected side of the rCRS seam.
- **SRS-VAR-005:** Reported caller variants MUST use a validated anchored REF/ALT representation and include only 1-based `position`, reference/alternate alleles, kind, and a direct `calls` array. Caller construction MUST preserve the alignment-selected event placement under `SRS-VAR-004`; optional post-calling representation normalization is owned by `SRS-VN-*`. Contig, classification, and normalization labels MUST NOT be duplicated in compact JSON.
- **SRS-VAR-006:** Every public variant-associated call MUST preserve its role, reference-oriented called `base`, co-located reference-oriented A/C/G/T primary-event channel heights, and uncalibrated `quality`. Original call index, ABIF PLOC, mapped call position, trace-strand primary/ambiguity, peak positions/sources, and vendor evidence MUST remain internal. Deletions MUST contain real flanks only and MUST NOT fabricate deleted-base signal/quality. A flanking call whose primary base is unresolved (`N`: its strongest channels tie, carry no signal, or all qualify) MUST be omitted rather than published or given fabricated evidence; supporting calls are always resolved, and a variant whose calls are all unresolved flanks is a typed failure.
- **SRS-VAR-007:** Variant construction MUST preserve observed call/reference mappings and the alignment-selected canonical indel topology. Reported allele anchoring MAY add the required adjacent reference base but MUST NOT relocate the event through a repeat or across the reference origin seam.
- **SRS-VAR-008:** Variant alleles MUST use the reference strand. Public call bases and A/C/G/T peak labels MUST be projected to the reference strand, including reverse alignments. Only the four co-located primary-event heights are emitted; selected peak positions/sources and broader per-call peak objects remain internal.
- **SRS-VAR-009:** Genotype, zygosity, homoplasmy, heteroplasmy fraction, phase, PHFinder, pathogenicity, and clinical significance are prohibited in DNA output.
- **SRS-VAR-010:** Every reported caller variant's 1-based anchor position MUST lie in at least one inclusive biological region of the target profile (SRS-PRF-004).
- **SRS-VAR-011:** Every SNV supporting call and every inserted-base supporting call MUST meet the configured maximum-channel peak floor and strictly exceed the configured relative-quality threshold, except that an insertion into a repeat the read bounds is judged on its placements along the repeat (SRS-VAR-020). Insertion flanks and deletion flanks MUST NOT be used for this supporting-evidence gate.
- **SRS-VAR-012:** A called SNV whose supporting call retains more than one co-localized qualifying channel under the active basecalling method MUST remain in observed/sample evidence but MUST be ineligible for clean SNV reporting with exclusion reason `mixed_supporting_dna`. This rule MUST NOT be generalized to insertions/deletions without a separately specified mixed-length method.
- **SRS-VAR-013:** A variant MUST be ineligible for reporting with reason `read_end` when any of its mapped calls is one its modality places at an edge of the read's usable signal (the `edge` of the call's verdict on its base, for a substitution, or on an indel, for an insertion or deletion), or lies within `variant_calling.read_end_margin` calls of a physical read end the modality does not vouch for (SRS-VAR-015); Sanger reads never vouch. The Sanger modality places at an edge every call within `variant_calling.read_end_margin` calls of an uninformative call: one outside the read's trim interval (SRS-QC-004), a masked call that does not anchor the alignment (a `dephased` call anchors), or a physical read end (SRS-CALL-013). A call the modality vouches for by its base only (scored, its bound withheld; SRS-CALL-014) supports a substitution but MUST NOT support an insertion, flank a deletion, or resolve a run's end: an insertion or deletion with such a mapped call MUST be ineligible with the core reason `base_only`. An insertion or deletion that changes the length of a run MUST NOT be `read_end` when the modality marks that run and its bounds as a bounded run before a post-repeat phase loss (SRS-CALL-016) and every mapped call lies on the run or its bounds; a substitution is never exempt (ADR-0076). Which calls the core then trusts depends on the alignment (SRS-CONS-003); that half of the rule stays in the core. A variant whose evidence call — a supporting call, or a flanking call of a deletion — is masked MUST be ineligible with the reason the modality gives that call's mask, verbatim (Sanger: `post_homopolymer` when the segment starts in the window after a repeat run, otherwise `dephased_signal`, `mixed_signal`, `weak_signal`, or `irregular_spacing` by phase state, SRS-CALL-012). An alignment column on a masked call MUST NOT be an SNV candidate, and an insertion with a masked inserted call MUST be excluded with its mask reasons. These rules MUST use only the read's own calls and signal and MUST NOT depend on primer identity or file names; ineligible variants remain observed evidence.
- **SRS-VAR-014:** Alignment and variant calling MUST consume a read only through the modality → core evidence contract (`ReadEvidence`: bases, optional profiles, the informative interval, the modality's reason order, and per call its placement (scored, or masked as anchoring or unresolved with its reason), its verdicts on its base, on an indel, and on a run's end, each with the modality's reasons and whether it lies at a signal edge, its mark in a bounded run before a post-repeat phase loss, and its second base). The modality adapter MUST own the modality-specific rules of SRS-VAR-011, SRS-VAR-012, and the mask reasons of SRS-VAR-013; the core MUST report modality labels verbatim in the order `placement_conflict` (SRS-VAR-017), region reason, the supporting calls' verdict reasons in the read's reason order (on their base for a substitution, on an indel for an insertion), `read_end`, `base_only`, `run_boundary` (SRS-VAR-016), `unresolved_flank` (SRS-VAR-018), mask reasons in mapping order, and MUST NOT branch on a modality label.
- **SRS-VAR-015:** The sequence modality MUST turn each reviewed consensus record into `ReadEvidence` whose every call is informative and unmasked and raises no support veto, and whose read ends are vouched for. A canonical base MUST carry a one-hot profile; an IUPAC ambiguity code MUST become an unresolved `N` whose profile shares its weight equally among the bases the code admits; `N` MUST carry no profile. The core MUST therefore not report an ambiguity code as a variant.
- **SRS-VAR-016:** A variant that changes the length of a run of one base — a substitution next to a call of its base, an insertion of one repeated base, or a deletion of one repeated base that leaves part of its run — MUST be ineligible with the core reason `run_boundary` when the read does not resolve the run end the edit touches. A run end is resolved by the call beyond the run when that call is informative and reads another non-`N` base, unmasked or anchoring-masked, or by a vouched read end. Insertions and deletions MUST need both run ends resolved and every call of the run unmasked; substitutions MUST need only the ends they lie on. The rule MUST use only `ReadEvidence` and the read's placement and MUST take no parameter.
- **SRS-VAR-017:** A reviewed consensus record whose name declares a reference interval (`<id>_<first>-<last>`, 1-based, closed, within the reference, as consensus segments are named) MUST be excluded from calling when its placement overlaps no part of that interval: every variant it observes MUST carry the core reason `placement_conflict` and none MUST be eligible. A record with any other name is placed as before. Such a record MUST also contribute no callable reference segments: its placement is the thing known to be wrong, so nothing it reads there may stand for the reference.
- **SRS-VAR-018:** A variant MUST be ineligible for reporting with the core reason `unresolved_flank` when any of its mapped calls — a supporting call, or a call flanking a deletion — is an unresolved call (`N`): an `N` observes no base (SRS-ALN-015), so it can neither support an edit nor bound where a deletion lies. A deletion neither of whose flanking calls reads a base MUST NOT be an observed variant: where its gap lies among unresolved calls is arbitrary, so it MUST be recorded only as excluded, with `unresolved_flank`. A substitution MUST also be `unresolved_flank` when its supporting call is vouched for by its base only, a neighbouring call in read order is not an unmasked canonical call of the informative interval trusted for more than its base (a masked call, even an anchoring one, `N`, or a call vouched for by its base only), and the substituted base is the reference base at an adjacent position: a shift of one position explains the call as the reference.
- **SRS-VAR-019:** In the `call` workflow (`dna call` and `SampleAnalysis::call`), a record's callable reference segments (SRS-ALN-015) MUST NOT include a position of a variant excluded from reporting: a substitution's position, a deletion's deleted positions, and both reference positions beside an excluded insertion's junction. An excluded call leaves its positions undecided rather than read as the reference; so does a candidate excluded before it is observed, such as an unresolved allele or an insertion or deletion no flank reads. Per-read sample evidence is not affected.
- **SRS-VAR-020:** An insertion whose inserted calls extend a repeat of their unit in the read (one base, or a unit such as AC), where the read bounds the run (no `run_boundary`), MUST be judged for support vetoes on its placements along that repeat: it raises none when some window of as many calls of the repeat, anywhere in the repeat and not necessarily next to the aligned insertion, is unmasked and carries no veto that applies to insertions: every such window is an equivalent placement of the same insertion. Which calls of a repeat the alignment takes as inserted is arbitrary (their 3'-most placement, SRS-ALN-012), so a veto on them alone MUST NOT decide the insertion's support. Variant calling and the consensus judge it with the same rule (SRS-CONS-003). Substitutions, insertions that extend no repeat, and deletions keep per-call vetoes.
- **SRS-VAR-021:** `call` given a consensus document (`dna.consensus/v1`, which MUST be its only input, of the requested sample and the supplied reference) and `SampleAnalysis::call` MUST call each consensus segment from the consensus's decisions without placing it on the reference again (ADR-0078): positions outside every site read the reference; a site's call is aligned against its own reference interval only, an `N` standing for the position it replaces and not callable; and every insertion and deletion takes its 3'-most sequence-equivalent placement over the segment (ADR-0047). The decided variants MUST be judged by the record rules (SRS-VAR-013 to SRS-VAR-020), and a length change of the reference run at the segment's first or last position MUST be excluded as `run_boundary`, since no read shows that run's outer end (ADR-0071). For a run of length evidence `phase_loss` or `reference_frame`, the 3'-most reference position, the deleted positions beside the run included, MUST NOT be callable, and a variant changing it, which a change of the run's length does, MUST be excluded as `run_boundary`. The run's other positions stay callable, since the reads show its composition (PROP-0008 step 3). A FASTA sequence given to `call` keeps the placement path.
