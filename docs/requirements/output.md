# Output Requirements

**Requirement namespace:** `SRS-OUT-*`

These requirements are part of the canonical [DNA SRS](SRS.md).

- **SRS-OUT-001:** A successful core CLI invocation MUST create exactly one command-specific result: analysis at `results/<trace-stem>.json`, reference-free basecalls at `results/<trace-stem>.basecalls.json`, or sample evidence at `results/<sample-id>.sample.json`. VCF/BCF, legacy JSON, duplicate compatibility output, and output-path/format compatibility options MUST NOT be created. Operational logging MUST remain a separate append-only sidecar.
- **SRS-OUT-002:** Analysis JSON MUST validate against Draft 2020-12 `docs/reference/schemas/analysis-v7.schema.json` and identify `dna.analysis/v7`. Basecall JSON MUST validate against `docs/reference/schemas/basecalls-v2.schema.json` and identify `dna.basecalls/v2`. Sample evidence JSON MUST validate against `docs/reference/schemas/sample-evidence-v8.schema.json` and identify `dna.sample_evidence/v8`. Strict configuration MUST remain schema version 5.
- **SRS-OUT-003:** Analysis and basecall JSON MUST include compact input/configuration identities, read call count and trim interval, merged candidate-noisy regions, and warning counts. Analysis MUST additionally include reference identity, selected alignment summary, and normalized variants with concise mapped calls; basecall MUST include primary, ambiguity, and retained sequences. Sample evidence JSON MUST include the sample identifier, shared reference/configuration identities, a deterministic read registry with reviewer-facing filenames plus SHA-256 identities and concise selected-alignment summaries, a deterministic pairwise overlap/admission graph, sparse differential loci with factorized support topology plus per-read state/base/quality and optional normalized A/C/G/T profile/noisy context, and normalized variant support with named reads plus peak/quality evidence while omitting consensus and interpretation. Software/build provenance MUST remain absent until a stable versioning strategy is defined.
- **SRS-OUT-004:** Analysis JSON MUST omit trace filenames, full primary/ambiguity/retained sequences, individual rolling windows, gapped alignment rows, operation runs, alignment score and redundant metrics, method constants, selected-peak positions/sources, call indexes/PLOC coordinates, penalties/calibration flags, vendor data, expanded configuration, variant contig/classification/normalization labels, and redundant warning fields. Basecall JSON MUST include full primary/ambiguity/retained sequences but omit reference, alignment, variants, rolling windows, per-call tables, peaks, penalties/calibration flags, and vendor data.
- **SRS-OUT-005:** JSON MUST use concise context-defined coordinate names: biological variant/locus `position` is 1-based; trim, reference-segment, and noisy-region `start`/`end` are 0-based half-open. Basecall primary and ambiguity lengths MUST equal `call_count`, and retained MUST equal the primary slice selected by trim.
- **SRS-OUT-006:** Core CLI output MUST be fully serialized, flushed, synchronized, and atomically published without overwriting. A failed core operation MUST leave no JSON result and MUST NOT replace an existing target.
- **SRS-OUT-007:** Deterministic output MUST omit timestamp, duration, host, random ID, local input/config paths, unordered maps, and all compatibility aliases.
- **SRS-OUT-008:** Rust MUST append timestamped, run-correlated INFO/WARN/ERROR stage records without writing operational records to application stdout/stderr. Standalone single-read operations MUST use `$DNA_LOG_DIR/<trace-stem>.log`; one sample operation MUST use exactly one `$DNA_LOG_DIR/<sample-id>.log` (default root `logs/`) and MUST route every nested trace-processing stage through that same sample logger rather than opening per-trace files. Records MUST cover each processing-stage boundary with concise aggregate metrics and timings, MUST remain one physical line, and MUST omit complete sequences, peak arrays, configured region contents, alleles, operation strings, and JSON bodies.
- **SRS-OUT-009:** Each excluded variant candidate MUST produce a WARN record containing its kind, contig, normalized position when available, and every rejection reason. Removed-variant records MUST omit reference and alternate alleles.
