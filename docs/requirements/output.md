# Output Requirements

**Requirement namespace:** `SRS-OUT-*`

These requirements are part of the canonical [DNA SRS](SRS.md).

- **SRS-OUT-001:** A successful core CLI invocation MUST create exactly one command-specific result: analysis at `results/<trace-stem>.json`, reference-free basecalls at `results/<trace-stem>.basecalls.json`, sample evidence at `results/<sample-id>.sample.json`, called variants at `results/<sample-id>.variants.json`, or notation at `results/<sample-id>.notation.json`. VCF/BCF, legacy JSON, duplicate compatibility output, and output-path/format compatibility options MUST NOT be created. Operational logging MUST remain a separate append-only sidecar.
- **SRS-OUT-002:** Analysis JSON MUST validate against Draft 2020-12 `docs/reference/schemas/analysis-v9.schema.json` and identify `dna.analysis/v9`. Basecall JSON MUST validate against `docs/reference/schemas/basecalls-v3.schema.json` and identify `dna.basecalls/v3`. Sample evidence JSON MUST validate against `docs/reference/schemas/sample-evidence-v10.schema.json` and identify `dna.sample_evidence/v10`. Variants JSON MUST validate against `docs/reference/schemas/variants-v1.schema.json` and identify `dna.variants/v1`. Notation JSON MUST validate against `docs/reference/schemas/notation-v1.schema.json` and identify `dna.notation/v1`. Strict configuration MUST remain schema version 7 and target profiles schema version 1.
- **SRS-OUT-003:** Analysis and basecall JSON MUST include compact input/configuration identities, read call count and trim interval, the read callability view (callable span, phase-state segments with repeat attribution and the shadow offsets of dephased segments, masked-call count; SRS-CALL-005), merged candidate-noisy regions, and warning counts. Analysis MUST additionally include reference and target-profile identities (SRS-PRF-007), selected alignment summary with masked bases and callable reference segments (SRS-ALN-015), and normalized variants with concise mapped calls; basecall MUST include primary, ambiguity, and retained sequences. Sample evidence JSON MUST include the sample identifier, shared reference/configuration/target-profile identities, a deterministic read registry with reviewer-facing filenames plus SHA-256 identities, the per-read callability view, a rejected-read registry (SRS-SAMPLE-027), and concise selected-alignment summaries, a deterministic pairwise overlap/admission graph, sparse differential loci with factorized support topology plus per-read state/base/quality and optional normalized A/C/G/T profile/noisy context, and normalized variant support with named reads plus peak/quality evidence, and, when the target profile declares notation, the per-read `notation` view (SRS-NOM-010 to SRS-NOM-012), while omitting consensus and interpretation. Software/build provenance MUST remain absent until a stable versioning strategy is defined.
- **SRS-OUT-010:** Variants JSON MUST include the sample identifier; shared reference, configuration, target-profile, and plugin identities; one entry per input record in input order with its identifier, sequence SHA-256, selected-alignment summary, and every observed variant with its eligibility and exclusion reasons; and, when the target profile declares notation, the per-read `notation` view. It MUST NOT carry modality evidence (peaks, quality, signal, or callability) and MUST NOT reconcile reads.
- **SRS-OUT-011:** Notation JSON MUST include the sample identifier; the reference, configuration, target-profile, and plugin identities; the source variants document's schema version and SHA-256; the per-read `notation` view of its eligible variants, equal to the in-process notation of the same profile; and, when the profile declares conformance, its rules and every finding with rule, read, and rendered calls.
- **SRS-OUT-004:** Analysis JSON MUST omit trace filenames, full primary/ambiguity/retained sequences, individual rolling windows, per-position callability features and masks, gapped alignment rows, operation runs, alignment score and redundant metrics, method constants, selected-peak positions/sources, call indexes/PLOC coordinates, penalties/calibration flags, vendor data, expanded configuration, variant contig/classification/normalization labels, and redundant warning fields. Basecall JSON MUST include full primary/ambiguity/retained sequences but omit reference, alignment, variants, rolling windows, per-position callability features and masks, per-call tables, peaks, penalties/calibration flags, and vendor data.
- **SRS-OUT-005:** JSON MUST use concise context-defined coordinate names: biological variant/locus `position` is 1-based; trim, callability-segment, callable-span, reference-segment, callable-reference-segment, and noisy-region `start`/`end` are 0-based half-open. Basecall primary and ambiguity lengths MUST equal `call_count`, and retained MUST equal the primary slice selected by trim.
- **SRS-OUT-006:** Core CLI output MUST be fully serialized, flushed, synchronized, and atomically published without overwriting. A failed core operation MUST leave no JSON result and MUST NOT replace an existing target.
- **SRS-OUT-007:** Deterministic output MUST omit timestamp, duration, host, random ID, local input/config paths, unordered maps, and all compatibility aliases.
- **SRS-OUT-008:** Rust MUST append timestamped, run-correlated INFO/WARN/ERROR stage records without writing operational records to application stdout/stderr. Standalone single-read operations MUST use `$DNA_LOG_DIR/<trace-stem>.log`; one sample, call, or notation operation MUST use exactly one `$DNA_LOG_DIR/<sample-id>.log` (default root `logs/`) and MUST route every nested trace-processing stage through that same sample logger rather than opening per-trace files. Records MUST cover each processing-stage boundary with concise aggregate metrics and timings, MUST remain one physical line, and MUST omit complete sequences, peak arrays, configured region contents, alleles, operation strings, and JSON bodies.
- **SRS-OUT-009:** Each excluded variant candidate MUST produce a WARN record containing its kind, contig, normalized position when available, and every rejection reason. Removed-variant records MUST omit reference and alternate alleles.
